ابتدا فایل تمرین را آماده کن

از فایل روز سوم یک نسخه با نام زیر ذخیره کن:

                                                                   
W01_D04_EPC_Validation.xlsx

شیت جدیدی بساز:

```
Lists
```

```
ستون 	عنوان
```

نکته: اعتبارسنجی امروز برای سلول‌های ورودی است. روی ستون‌هایی که خروجی فرمول پاک‌سازی‌اند، انتظار نداشته باش Data Validation نتیجه‌ی محاسبه را مسدود کند.

 اعمال قوانین روی جدول EPC — ۲۵ دقیقه

قوانین زیر را پیاده کن:
ستون 	قانون
ProjectID 	فهرست پروژه‌ها
PackageID 	فهرست وابسته به پروژه
ApprovedFinish 	تاریخ عددی، برابر یا بعد از شروع
ActualDelivery 	خالی یا تاریخ معتبر تا امروز
Status 	چهار وضعیت مجاز
Quantity 	عدد صحیح مثبت

برای همه‌ی قوانین، پیام راهنما و Stop تنظیم کن.

برای ستون‌های اجباری، Ignore blank را غیرفعال کن، اما آن را تضمین پرشدن ستون ندان؛ حذف محتوا و ردیف‌های ناقص باید در کنترل کیفیت هم بررسی شوند.
۱۱. کنترل سازگاری وضعیت و تحویل — ۲۰ دقیقه

در H2 بنویس و به پایین گسترش بده:

                                                                    excel
=IF(AND(F2="Delivered",E2=""),"Missing delivery date",IF(AND(F2<>"Delivered",E2<>""),"Check status","OK"))

دو خطا را پیدا می‌کند:

    وضعیت Delivered است، اما تاریخ تحویل نداریم.
    تاریخ تحویل داریم، اما وضعیت Delivered نیست.

کنترل اعتبار خود وضعیت

در ستونی جدا:

                                                                    excel
=COUNTIF(StatusList,F2)=1

این کنترل برای پیدا‌کردن مقادیری مفید است که مثلاً با Paste وارد شده‌اند.
کنترل تطابق پروژه و بسته

در ستون دیگر:

                                                                    excel
=IFERROR(COUNTIF(INDIRECT(SUBSTITUTE(A2,"-","_")),B2)=1,FALSE)

اگر پروژه عوض شود اما بسته‌ی قبلی باقی بماند، این ستون می‌تواند FALSE شود.

IFERROR در اینجا خطای نام پروژه یا محدوده‌ی ناموجود را به نتیجه‌ی نامعتبر تبدیل می‌کند؛ آن را معتبر فرض نمی‌کند.

برای این کنترل‌ها با Conditional Formatting، مقدار FALSE یا پیام غیر از OK را قرمز کن.
۱۲. آزمون تخریب کنترل‌شده — ۲۰ دقیقه

عمداً فایل را با این ورودی‌ها امتحان کن:
آزمون 	انتظار
تایپ Complete در Status 	مسدود شود
تایپ -5 در Quantity 	مسدود شود
تایپ 2.5 در Quantity 	مسدود شود
ورود پایان قبل از شروع 	مسدود شود
ورود تاریخ واقعی فردا 	مسدود شود
Delivered بدون تاریخ تحویل 	ستون کنترل خطا بدهد
انتخاب بسته، سپس تغییر پروژه 	ناسازگاری در ستون کنترل دیده شود
Paste مقدار نامعتبر در Status 	ممکن است از Validation عبور کند؛ کنترل باید آن را پیدا کند

Paste معمولی ممکن است خود قانون Validation را هم بازنویسی کند. برای داده‌ی ورودی از Paste Special → Values استفاده کن، ولی حتی آن را هم تضمین اجرای اعتبارسنجی ندان.

برای بررسی سلول‌های نامعتبرِ دارای قانون:

                                                                    text
Data → Data Validation → Circle Invalid Data

اعمال Validation روی داده‌های قدیمی، آن‌ها را خودکار اصلاح نمی‌کند.
۱۳. آزمون گسترش Table و مرور — ۱۵ دقیقه

یک ردیف جدید به جدول اضافه کن و بررسی کن:

    دراپ‌داون‌ها موجودند؟
    بسته‌ها به پروژه‌ی همان ردیف وابسته‌اند؟
    فرمول‌های کنترل گسترش یافته‌اند؟
    پیام Stop هنوز فعال است؟

به انتقال خودکار قوانین اعتماد نکن؛ آن را آزمایش کن، مخصوصاً وقتی قوانین ستون یکدست نیستند.

سه مورد در دفترچه‌ی اشتباهات ثبت کن:

    استفاده از $A$2 به‌جای $A2 باعث وابستگی تمام ردیف‌ها به یک پروژه شد.
    تغییر پروژه، بسته‌ی قدیمی را پاک نکرد.
    Paste توانست داده‌ی نامعتبر را وارد کند؛ ستون کنترل آن را شناسایی کرد.
