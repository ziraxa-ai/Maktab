# بخش اول: درک مدل ذهنی `let … in`

ساده بگیم : 

`let`
یک بلوکی را برای  تعریف نام‌ها و محاسبات تشکیل می دهد .
##### که در نهایت از ،
`in`
برای مشخص‌کردن نتیجه کل عبارت و تعین آن برای یک متغیر می باشد .

### یک مثال با چند گام 
let
    Price = 100,
    Quantity = 3,
    Total = Price * Quantity
in
    Total



خروجی آن :

300

#### آیا حتما باید قبل از in محاسبات انجام شود و عبارت نوشته شد؟

خیر میتوانیم متغیرها رو در let تعریف کنیم و در in عبارت محاسباتمون رو بنویسیم، مثل:
			let
			    Price = 100,
			    Quantity = 3
			in
			    Price * Quantity



**نکته هر خط نشانه از یک step نیست، به عنوان مثال در مثلا قبلی:**
			let
			    Price = 100,
			    Quantity = 3,
			    Total =
			        Price
			        *
			        Quantity
			in
			    Total



**نکته دیگر : زبان M مثل پایتون نیست که از بالا به پایین اجرا شودو ترتیب ندارد به عنوان مثال ببینیم:**

در پایتون داریم:
    
			Price = 100
			Quantity = 3
			Total = Price * Quantity

اما اگر بنویسیم :

			Total = Price * Quantity
			Price = 100
			Quantity = 3

#### به خطا بر می خوریم.

اما در **M** کد زیر درست است:

			let
				Total = Price * Quantity,
				Price = 100,
				Quantity = 3
			in
				Total

### نکته مهم بهتر است برای منظم بودن در کد نویسی، سهولت خوانایی و قابلیت گسترش کد ترتیب درست را در پیش بگیریم.


**اعضای let هنگام نیاز ارزیابی می شوند؛ این بخشی از **ارزیابی تنبل** در زبان M است.**

### ## نقش کاما ( , ) در `let`

تعریف‌های داخل `let` با ویرگول انگلیسی `,` از یکدیگر جدا می‌شوند.

## دو نکته مهم :
			
			let
			    A = 10
			    B = 20
			in
			    A + B
				
اینجا چون بین تعریف `A` و `B` جداکننده ( , ) وجود ندارد؛ این کد معتبر نیست.

			let
			    A = 10,
			    B = 20,
			in
			    A + B

 و در اینجا ویرگول بعد از `B = 20` اضافه است.

 ## متغیرها
** همانند یک ظرفی است که در آن مقداری میریزیم** 
- چگونه مقدار دهی می کنیم؟ **به کمک مساوی**
- چه مقدار هایی می توانیم در آن بریزیم؟

  #### حالت اول: مقدار مستقیم

                                                                    
		Count = 10

#### حالت دوم: محاسبه

                                                                    
		Total = Price * Quantity

#### حالت سوم: فراخوانی تابع

	                                                                    
		CleanText = Text.Trim(RawText)

**نکته :تابع Text.Trim فاصله‌های ابتدا و انتهای متن را حذف می‌کند.(فعلا فقط گوشه ذهنت باشه.)**


### ما می توانیم به دو حالت ساده و ویژه متغیرهامون رو نام گذاری کنیم.
- نام ساده:
  					CleanedText


- نام دارای فاصله، با نگارش ویژه:
  					#"Cleaned Text"

**خوب حالا تفاوتشون چیه؟**

					"Cleaned Text"
یک **مقدار متنی** است.
اما؛
					#"Cleaned Text"

یک شناسه **نقل قول شده** است، حالا کاربردش چیه ؟ (اینجا رو یکم دقت کن)
در زبان‌های مختلف برنامه نویسی ما قوانینی برای نام گذاری متغیرها داریم، یکی از این قوانین در زبان M گذاشتن،(Space) و یا کارکترهای خاص ممنوع می باشد. پس ما ابتدا توسط، (" ") نام را تبدیل به متن می کنیم، سپس به کمک **#** آن را به عنوان، 

#### یک نکته دیگر راجب انتخاب نام متغیرها، 
در یک let ما نمی توانیم یک نام را دوبار تعریف کنیم، تا مقدار جدیدی در آن به روز رسانی شود.
مثال اشتباه:

		let
		    Price = 100,
		    Price = Price * 2
		in
		    Price


به جای آن از :

		let
		    OriginalPrice = 100,
		    DoubledPrice = OriginalPrice * 2
		in
		    DoubledPrice

در واقع ما توی پاکسازی داده هم مدل ا دنبال می کنیم:

		RawData → CleanedData → TypedData

هر نام، نتیجه یک **مرحله** را بیان می‌کند؛ قرار نیست داده قبلی را با نسبت دادن به نامی مجدد بازنویسی کنیم.
این توصیف، مدل منطقی کد است و به معنی **کپی کامل فیزیکی** داده در حافظه برای هر گام نیست.


#### حالا چون ما برای کار با Power Query  از زبان M استفاده میکنیم، حتما خروجیمون جدول هستش ؟

یک Query در M می‌تواند نتیجه‌ای از این جنس‌ها داشته باشد:
| نوع نتیجه | مثال |
| :--- | :--- |
| عدد | 100 |
| متن | "Clean Data" |
| مقدار منطقی | true |
| لیست | {10, 20, 30} |
| رکورد | [Name = "Sara", Age = 28] |
| جدول | جدول مشتریان |
| تابع | تابع پاک‌سازی متن |


فعلاً لازم نیست لیست و رکورد را یاد بگیری

# بخش سوم.گام‌ها چگونه به هم وابسته می شوند؟

## ساخت یک زنجیره تبدیل
با یک مثال پیش میرویم،کد زیر را اجرا کنید؛

				
				let
				    RawText = "  machine learning  ",
				    TrimmedText = Text.Trim(RawText),
				    UpperText = Text.Upper(TrimmedText)
				in
				    UpperText

خروجی:

				MACHINE LEARNING

### حالا بیاید با هم رابطه بین این گام ها را بررسی کنیم:
#### گام اول(داده خام را مقدار دهی کردیم):

				RawText = "  machine learning  "

#### گام دوم(فاصله های اضافی اول و آخر متن را حذف کردیم):

				TrimmedText = Text.Trim(RawText)

**خروجی:**

				"  machine learning  " =>   "machine learning"

#### گام سوم(اومدیم حروف را به بزرگ تبدیل کردیم):
				UpperText = Text.Upper(TrimmedText)

**خروجی:**

				"MACHINE LEARNING"

پس رابطه گام‌ها:

    
													RawText
													   ↓
													TrimmedText
													   ↓
													UpperText

این مقدارها ممکن است به‌عنوان دسته‌های متفاوت دیده شوند:

                                                                    text
tehran
TEHRAN
 tehran

اگر قرار است شهر یک متغیر دسته‌ای باشد، چنین تفاوت‌هایی می‌توانند دسته‌های ظاهراً متفاوت اما معنایی یکسان بسازند.

هدف ما:
CustomerID 	Name 	City
1 	Ali 	TEHRAN
2 	Sara 	SHIRAZ
3 	Reza 	TEHRAN
۱۹. کد کامل پروژه

کد زیر را در یک Blank Query اجرا کن:

				let
				    Source = #table(
				        type table [
				            CustomerID = Int64.Type,
				            Name = text,
				            City = text
				        ],
				        {
				            {1, "  Ali  ", " tehran "},
				            {2, " Sara ", "SHIRAZ "},
				            {3, "Reza   ", " tehran"}
				        }
				    ),
			
			    TrimmedNames = Table.TransformColumns(
			        Source,
			        {
			            {"Name", Text.Trim, type text}
			        }
			    ),
			
			    TrimmedCities = Table.TransformColumns(
			        TrimmedNames,
			        {
			            {"City", Text.Trim, type text}
			        }
			    ),
			
			    StandardizedCities = Table.TransformColumns(
			        TrimmedCities,
			        {
			            {"City", Text.Upper, type text}
			        }
			    )
			in
			    StandardizedCities

این مثال عمداً چند گام جدا دارد تا جریان تبدیل‌ها واضح باشد.

    هدف فعلی حفظ‌کردن سینتکس جدول و فهرست‌ها نیست. در این درس باید بتوانی ورودی، وابستگی و خروجی هر گام را تشخیص بدهی.

# بریم برای بررسی گام‌به‌گام پروژه
### گام اول: ساخت جدول نمونه

                                                                    
		Source = #table(...)

در اینجا #table یک جدول درون خود کد می‌سازد.

بخش زیر ساختار ستون‌ها و نوع داده آن‌ها را مشخص می‌کند:

	type table [
	    CustomerID = Int64.Type,
	    Name = text,
	    City = text
		]

    CustomerID: عدد صحیح ۶۴ بیتی؛
    Name: متن؛
    City: متن.

بخش بعدی سطرهای جدول است:

                                                                    
		{
			{1, "  Ali  ", " tehran "},
			{2, " Sara ", "SHIRAZ "},
			{3, "Reza   ", " tehran"}
		}

هر گروه داخلی، مقادیر یک سطر را به ترتیب ستون‌ها مشخص می‌کند.

نام Source یک نام قراردادی و رایج است، نه کلیدواژه ویژه زبان.
گام دوم: پاک‌سازی نام‌ها

			
			TrimmedNames = Table.TransformColumns(
			    Source,
			    {
			        {"Name", Text.Trim, type text}
			    }
			)

معنی ساده:

    جدول Source را بگیر، تابع Text.Trim را روی مقدارهای ستون Name اعمال کن و نوع خروجی آن ستون را متن قرار بده.

ساختار دستور تبدیل:


		{"Name", Text.Trim, type text}

		جزء 	معنی
		"Name" 	نام ستون مورد نظر
		Text.Trim 	تابع تبدیل هر مقدار
		type text 	نوع ستون خروجی

در اینجا Text.Trim را بدون پرانتز داده‌ایم، چون خود تابع را به تابع دیگری می‌دهیم تا روی مقدارهای ستون اجرا شود.
